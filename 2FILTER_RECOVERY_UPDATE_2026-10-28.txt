NERC TPL CA - 2Filters power-flow recovery update - 2026.10.28

WHAT THE 2FILTERS FILE ACTUALLY DOES

2Filters&Monitor_Settings&EquivalenceVACAR&SOCO.aux is a 2,603-line case
preprocessor. It is not limited to two display filters.

Near the beginning it marks a fixed list of areas as retained, marks all other
areas external, and runs PowerWorld's Equivalence command. It then changes many
solution controls, including AGC, generator limits, taps, shunts, phase shifters,
iteration limits, and convergence tolerance.

It creates many filters and data-grid/display definitions. It defines limit sets,
turns monitoring off for every area, and then turns monitoring back on for area
343 (SCEG) from 30 through 9999 kV. It changes contingency-analysis settings,
opens selected SCEG generators, forces two specific swing generators closed,
and changes AGC capability on a fixed list of nuclear generators.

It also has two external dependencies:

  LoadAUX("BreakerData.aux")

  Renumber3WXFormerStarBuses("\\mbu.dominionnet.com\data\TRANSMISSION OPERATIONS CENTER\7T\Data2\DESC_Trans_Planning\LTR_Basecases\Current Cases\AUX Manipulating\ThreeWindingStarBuses.txt",COMMA)

The PowerWorld session must be able to resolve/read both files. The input case
must also contain the expected retained areas, SCEG area 343, and referenced
devices. A missing dependency or incompatible object is an AUX-processing error,
not a power-flow solve error, and this update deliberately does not hide it.

WHY THE PYTHON RUN STOPPED

After applying manipulation AUX files, the Python workflow previously called
SolvePowerFlow once. Equivalencing can leave a valid case that needs a different
convergence tolerance or disabled area-interchange AGC for its first solution.

The original VB application contained a specific recovery routine for this. It
saved a temporary post-equivalence PWB, reopened a clean copy between attempts,
relaxed convergence tolerance, and then retried with AGC disabled. The Python
conversion had not carried that recovery routine over.

WHAT CHANGED

A successful initial SolvePowerFlow behaves exactly as before. It performs no
additional saves or retries.

If the initial solve fails, the workflow now:

  1. Closes the potentially dirty failed case.
  2. Reopens the original input and reapplies its manipulation AUX files.
  3. Saves a unique post-manipulation recovery PWB under
     %LOCALAPPDATA%\NERC_TPL_CA_PY.
  4. Retries from that same clean snapshot with convergence tolerances of
     0.01, 0.1, and 1.0.
  5. Retries with area-interchange AGC disabled at tolerances of
     0.001, 0.01, 0.1, and 1.0.
  6. Continues normally as soon as a solve succeeds.

Every attempt is logged. The recovery PWB is deleted after success. If all seven
retries fail, it is retained and its path is logged for investigation. Recovery
is bounded, respects Stop safely between attempts, and never loops forever.

This recovery also applies to the base-case check, combined-case preparation,
PTI contingency creation, and normal Go! analysis because they share the same
case-conditioning workflow.

No AUX, Resource, or VB source file was edited.
